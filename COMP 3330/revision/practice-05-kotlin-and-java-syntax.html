Practice: Kotlin and Java syntax

Chapter 5 is the syntax the course assumes everywhere else. These exercises trace small programs line by line, in Kotlin first with Java beside it, until the differences stop surprising you.

Background: Kotlin and Java syntax.

Quiz: types, variables and nulls

Q1

What does val mean in Kotlin, and what happens on re-assignment?

Chapter 5's Variables slide: val a: Int = 1 is the immutable version, var a: Int = 1 the mutable one, and "Value re-assignment to a and b will cause error" in the immutable version. Type inference works in both (val a = 1 infers Int).

Q2

Given var s2: String? = "hku", what is the type of s2?.length and why?

Chapter 5 states it: "l is assigned null if S2 is null. So the type of l is Int?" and later "The type of expressions a?.length and b?.length is Int?". The current value is irrelevant; the declared type decides.

Q3

What array does val num = Array(3, {i -> i*1}) create?

Chapter 5: the Array constructor takes the size and a function that accepts the index of an element and returns its initial value. With size 3 the indices are 0, 1, 2 and the lambda returns i*1, so the content is 0, 1, 2, matching the slide's own equivalence: "equivalent to val num = arrayOf(0, 1, 2)".

Q4

You write class Employee(name: String, val salary: Int): Person(name). What must be true about Person?

Chapter 5, next to the Employee example: "All classes in Kotlin are final by default. We need to add the open keyword so that we can inherit from our Person class." The subclassing syntax is fine only once Person is open.

Q5

For fun calculate(num1: Int, num2: Int = 2, num3: Int = 4), which call sets num3 to 5 while leaving num2 at its default?

Chapter 5 shows exactly this: parameter names can be used in calls, and calculate(1, num3 = 5) leaves num2 at its default 2. calculate(1, 5) would set num2 = 5 positionally. num1 has no default, so it must be provided.

Source: COMP3330_Ch05_Syntax.pdf, slides 8-10, 15-16, 25.

Exercise 1: default parameters and named arguments

Exercise 1 skill: tracing parameter binding with defaults and names easy

Given the Chapter 5 function:

Kotlin
fun calculate(num1: Int, num2: Int = 2, num3: Int = 4) {
    println("$num1 $num2 $num3")
}

State the three printed values for each call: (a) calculate(1, 3) (b) calculate(1, num2 = 3) (c) calculate(1, num3 = 5) (d) calculate(num3 = 5, num1 = 1). Then answer the lecture's own challenge: how do you provide the 1st and 3rd parameters while missing the 2nd?

Step 1: bind positionally where no name is given

(a) calculate(1, 3): num1 = 1, num2 = 3 (positional, left to right), num3 falls back to 4.

Step 2: bind by name where names are used

(b) num1 = 1, num2 = 3 by name, num3 = 4 default. (c) num1 = 1, num2 = 2 default, num3 = 5 by name. (d) names decide placement, so num1 = 1, num2 = 2 default, num3 = 5; the argument order in the call does not matter once names are attached.

Step 3: the challenge

Provide the 1st positionally and the 3rd by name: calculate(1, num3 = 5). The 2nd keeps its default because nothing names or positions it.

Full answer

(a) 1 3 4. (b) 1 3 4. (c) 1 2 5. (d) 1 2 5. Challenge: calculate(1, num3 = 5), or equivalently calculate(num1 = 1, num3 = 5). The rule chain: unnamed arguments fill parameters left to right, named arguments bind to their parameter and can skip others, and anything still unbound takes its default.

Trap

Reading calculate(1, 5) as "num1 and num3". Positional means left to right: 5 lands in num2, and num3 stays 4. Names are the only way to skip a middle parameter with a default.

Source: COMP3330_Ch05_Syntax.pdf, slides 8-9 (default values, named parameters).

Exercise 2: null safety, line by line

Exercise 2 skill: predicting types and values of nullable expressions medium

For each line, state the declared type of the result and the value or error it produces:

Kotlin
var s1: String = "hku"
val l1 = s1.length
var s2: String? = "hku"
val l2 = s2.length
val l3 = s2?.length
var s3: String? = null
val l4 = s3?.length
val a = "Computer"
val b: String? = null
println(b?.length)
println(a?.length)

Then explain the difference in shape between this Java method and its one-line Kotlin version:

Java
public ZipCode getZipCode(User user) {
    if (user != null) {
        if (user.address != null) {
            return user.address.zipCode;
        }
    }
    return null;
}
Kotlin
fun getZipCode(user: User?): ZipCode? {
    return user?.address?.zipCode
}
Step 1: use the declared type, not the current value

l1: Int, value 3 (s1 is non-null, so .length is safe). l2: the compiler reports an error ("variable 'S2' can be null") even though s2 currently holds "hku", because its type String? allows null.

Step 2: follow the safe call

l3: Int?, value 3 (s2 non-null today). l4: Int?, value null (s3 is null, so the whole expression short-circuits to null). The rule from the slides: l is assigned null if the reference is null, so the type is Int?.

Step 3: the print statements

println(b?.length) prints null. println(a?.length) prints 8. a is non-null so the safe call is unnecessary, but the expression type is still Int? and the value is 8.

Step 4: Java versus Kotlin shape

The Java version nests two null checks and falls through to null; the Kotlin version is one line because the safe-call chain tim?.department?.head?.name (and user?.address?.zipCode) returns null if any property in the chain is null. Same behaviour, explicit in Java, encoded in the operator in Kotlin.

Full answer

l1: Int = 3. l2: compile error ("S2 can be null"). l3: Int? = 3. l4: Int? = null. println(b?.length) prints null; println(a?.length) prints 8. The Kotlin getZipCode is the Java method with the null-guard nesting replaced by the safe-call chain: each ?. propagates null instead of requiring an if.

Trap

Two traps. Deciding l2 by reading the current value ("s2 holds 'hku', so it compiles"): Kotlin decides by type, and String? can hold null. And expecting println(a?.length) to complain or print differently because the safe call is unnecessary: the slide marks it as an unnecessary safe call and the output is the plain value 8.

Source: COMP3330_Ch05_Syntax.pdf, slides 13-18 (null safety, safe-call chains, Java comparison).

Exercise 3: how objects get built

Exercise 3 skill: tracing constructors, init blocks and inheritance requirements medium

Given these Chapter 5 classes:

Kotlin
class Person(val name: String, val age: Int? = null) {
    init {
        println("Hello, I'm $name")
    }
}

class Car(val id: String, val type: String) {
    constructor(id: String) : this(id, "unknown")
}

Answer: (a) what does val person1 = Person("Sam", 20) print and what are person1's property values? (b) same for val person2 = Person("Priscilla"). (c) for val car2 = Car("2"), what are id and type? (d) where would you put code that must run on every construction, and why is the primary constructor not the place? (e) what single keyword makes Employee(name: String, val salary: Int): Person(name) legal?

Step 1: trace Person

The primary constructor takes name and age (age defaults to null). The initializer block runs after the primary constructor and prints "Hello, I'm $name". So Person("Sam", 20) prints "Hello, I'm Sam"; name = "Sam", age = 20, both read-only (val). Person("Priscilla") prints "Hello, I'm Priscilla"; age is null because the default kicks in.

Step 2: trace Car

Car("2") hits the secondary constructor, which delegates to the primary with this(id, "unknown"). So id = "2", type = "unknown".

Step 3: the init rule and the open rule

"We cannot put any code in the primary constructor"; initialization code goes in an initializer block prefixed with init, called after the primary constructor, and class fields are accessible there. For inheritance: "All classes in Kotlin are final by default. We need to add the open keyword so that we can inherit from our Person class."

Full answer

(a) Prints "Hello, I'm Sam"; name = "Sam", age = 20. (b) Prints "Hello, I'm Priscilla"; age = null. (c) id = "2", type = "unknown" via the secondary constructor delegating with this(...). (d) In an init block: the primary constructor cannot contain code, and init runs after it on every construction. (e) open, on Person's declaration.

Trap

Assuming Kotlin classes extend anything by default is backwards: they are final by default. Writing the Employee subclass without open on Person is the compile error the lecture warns about. Second trap: expecting the init block to run before the constructor parameters are assigned: it runs after the primary constructor, which is exactly why $name is already available in it.

Compare

Java needs far more code for the same Person: fields, two overloaded constructors assigning this.name and this.age. Kotlin's one-liner plus default value replaces both. No "new" keyword in Kotlin: instantiation is constructor invocation, val person1 = Person("Sam", 20).

Source: COMP3330_Ch05_Syntax.pdf, slides 20-25 (class declaration, init, secondary constructors, inheritance).

Exercise 4: arrays and string interpolation

Exercise 4 skill: predicting array contents and interpolated output easy

(a) What are the contents of val sq = Array(4, {i -> i*i})? (b) What exactly does this loop print, including spacing?

Kotlin
val num = arrayOf(1, 2, 3, 4)
for (i in 0..num.size-1) {
    print(" " + num[i])
}

(c) A Song has id, title and author properties. Rewrite this toString as a single expression-bodied function using string interpolation, and state the printed form for id=7, title="HKU", author="Tim".

Kotlin
override fun toString(): String {
    return "Song{id=" + id + ", title='" + title + "', author='" + author + "'}"
}
Step 1: array constructor semantics

The constructor's function receives the index and returns that element's initial value. For size 4, indices 0-3 give 0, 1, 4, 9.

Step 2: the loop

0..num.size-1 is the inclusive range 0..3, so all four elements print in order, each preceded by one space: " 1 2 3 4" (one line, no trailing newline from print).

Step 3: interpolation

$ substitutes a variable's value inside the string, so the concatenation collapses into one template. The three forms in the lecture are equivalent; the shortest is expression-bodied: override fun toString() = "Song{id=$id, title='$title', author='$author'}".

Full answer

(a) [0, 1, 4, 9]. (b) " 1 2 3 4". (c) override fun toString() = "Song{id=$id, title='$title', author='$author'}" which prints Song{id=7, title='HKU', author='Tim'}. Chain: Array(size, function-of-index) fills by index; .. is inclusive at both ends; $ pulls the variable's value into the string.

Trap

Reading Array(4, {i -> i*i}) as four copies of 4, or as starting at 1. The lambda receives the element's index (0-based) and returns its initial value, so a size-4 array yields indices 0 through 3. Same trap as the lecture's own Array(3, {i -> i*1}) = [0, 1, 2].

Source: COMP3330_Ch05_Syntax.pdf, slides 11-12 (arrays), 19 (string interpolation).

Mixed exercise: hardening the BMI calculator

Exercise 5 skill: applying null safety and typing to real activity code hard

This pulls Chapter 4's wiring in with Chapter 5. Tutorial 1's BMI calculator declares its fields as nullable, finds them in onCreate, and computes on button click:

Kotlin
class MainActivity : AppCompatActivity() {
    private var height: EditText? = null
    private var weight: EditText? = null
    private var result: TextView? = null

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContentView(R.layout.activity_main)
        height = findViewById<EditText>(R.id.editText1)
        weight = findViewById<EditText>(R.id.editText2)
        result = findViewById<TextView>(R.id.textView)
    }

    fun calc(v: View?) {
        val h = height!!.text.toString().toFloat()
        val w = weight!!.text.toString().toFloat()
        val bmi = w / h / h
        result!!.text = "Your BMI is: $bmi"
    }
}

(1) For each of the three fields, state its type and why the "!" is used at the call site. (2) Which line of Chapter 4's example replaced the findViewById casts used elsewhere in the course? (3) Write the Java equivalent of calc's listener-style version with the required capture rule. (4) The XML wires the button to calc via the onClick attribute (Tutorial 1). What does the argument v represent?

Step 1: the field types

height, weight are EditText? and result is TextView?; the "?" says the property can hold null, matching Chapter 4's note that "? notation indicates that a data type can take a null value". The "!!" asserts the value is non-null and, per the same slide, "throws an exception if the value is null". This is safe only because onCreate assigns all three before any click.

Step 2: the findViewById form

Here findViewById<EditText>(...) supplies the target type directly, unlike Chapter 4's findViewById<View>(...) as EditText cast form. Both reach the same widgets through R.id values created by the @+id declarations in activity_main.xml.

Step 3: the Java shape

Java anonymous listeners capture locals, so the view references must be final, per the Chapter 4 rule: "final = always contain the same value". Java also needs casts out of findViewById.

Step 4: the callback argument

calc is invoked as the button's click handler, and the framework passes the clicked View as the parameter; Chapter 4's Java example names it dummy. It is the widget that was clicked, here the BMI button.

Full answer

(1) EditText? and TextView?: nullable because they start as null and are assigned in onCreate; "!!" asserts non-null and throws if violated. (2) The typed findViewById<EditText>(...) form replaces Chapter 4's findViewById<View>(...) as EditText cast form; both resolve through R.id. (3) The listener-shaped Java version, beside its Kotlin twin:

Kotlin
val calc = findViewById<View>(R.id.calc) as Button
val listener = View.OnClickListener {
    val h = height!!.text.toString().toFloat()
    val w = weight!!.text.toString().toFloat()
    val bmi = w / h / h
    result!!.text = "Your BMI is: $bmi"
}
calc.setOnClickListener(listener)
Java
final EditText height = (EditText) findViewById(R.id.editText1);
final EditText weight = (EditText) findViewById(R.id.editText2);
final TextView result = (TextView) findViewById(R.id.textView);
Button calc = (Button) findViewById(R.id.calc);

Button.OnClickListener listener = new Button.OnClickListener() {
    public void onClick(View v) {
        double h = Double.parseDouble(height.getText().toString());
        double w = Double.parseDouble(weight.getText().toString());
        double bmi = w / h / h;
        result.setText("Your BMI is: " + bmi);
    }
};
calc.setOnClickListener(listener);

(4) v is the View that was clicked.

Trap

The "!!" assertions look like a style choice; they are a contract. If any click handler ran before onCreate finished assigning (or a future refactor moves the findViewById calls), the assertion throws. The Kotlin way to keep the type system happy without "!" is to keep the code in one place where assignment has provably happened. The course's own examples lean on "!!" with that assumption made explicit.

Why it matters

This is the pattern every app in the course shares: nullable fields, findViewById in onCreate, a listener doing the work on click. Once you can read this, the Card 24 code in Tutorial 3 is the same shape with more widgets.
