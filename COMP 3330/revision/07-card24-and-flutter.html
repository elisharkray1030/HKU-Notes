Card 24 and Flutter

Tutorials 2 and 3 build one real Android app end to end; Tutorial 4 opens the door to Flutter. This page walks the Card 24 codebase the way you should walk any unfamiliar Android project, then explains what Flutter's widget-and-setState model changes.

The game, specified like an exam question

Card24 is an arithmetical card game: manipulate four poker cards' numbers so the end result is 24. Cards run 1 to 13 (Ace, Jack, Queen, King represent 1, 11, 12, 13), and the four operations plus brackets are allowed. The lecture's worked hand: for four cards, one solution is (13 – 5) × (1 + 2) = 24.

The full specification, which is worth reading as a requirements document:

  • Start game: randomly pick 4 non-duplicate cards from 52 (jokers excluded) and display them. The player then builds a formula from these cards and the arithmetic symbols.
  • Formula: the four symbols "+", "-", "x", "/" plus open and close brackets. Evaluation order: bracket items, then multiplication/division, then addition/subtraction. The slide's example "(1) + (11 – 2) x 6": (1) = 1, (11 – 2) = 9, 9 × 6 = 54, 1 + 54 = 55.
  • Input sanity rules: a card or "(" can only be selected as the first item, or after an arithmetic symbol or "(". A symbol or ")" can only be selected when the last selected item is a card or ")". These rules exist to reject nonsense like "()1+/12".
  • Winning: no error in the formula, all four cards used exactly once, and the result equals 24.
  • Components: 4 card buttons (ImageButtons), 6 symbol buttons ("+","-","x","/","(",")"), 1 TextView showing the current formula, 2 buttons for new game and clear, and 1 "=" button that evaluates the formula and tells the player win or lose.
  • Edge cases: each card can be selected only once (button disabled after use, with some indicator); "new game" and "clear" re-enable buttons and update the formula display; an invalid formula at "=" counts as wrong (the player loses), with an error message.
Exam angle

This spec is the model for "given a scenario, list the UI components and the state your class must track". Every edge case in it maps to a field in the code below.

Reading a real Android codebase

When you open someone else's Android project, read in the same four moves every time: find the UI (the layout XML), find the wiring (onCreate), find the state (the fields), find the behaviour (methods and listeners). Card 24, walked:

1. The UI (Tutorial 2)

The layout is nested: the outermost layout is a ScrollView while the inner layouts are LinearLayouts: ScrollView so the whole board can scroll on small screens, LinearLayouts to stack rows of buttons. A drawable resource back_0.png goes in the drawable folder as the face-down card image, and images are resolved with resources.getIdentifier("back_0", "drawable", "hk.hkucs.card24"): the resource lookup that stands in for R.drawable.back_0 when names are built at run time.

2. The state

Kotlin
private lateinit var cards: Array<ImageButton>   // the four card buttons
private lateinit var expression: TextView        // the formula display
private lateinit var data: Array<Int>            // card values 1..13
private lateinit var card: Array<Int>            // card ids 1..52
private lateinit var imageCount: Array<Int>      // clicks per card (0 or more)
private var rePick: Button? = null               // new game
private var checkInput: Button? = null           // "="
private var clear: Button? = null
private var left, right, plus, minus, multiply, divide: Button? = null

State to hold the game: four buttons, four values, four card ids, four use-counts, and the formula text. If you can name the state, you can write the app.

3. The wiring

Everything is bound in onCreate() with findViewById, and each button gets a listener (page 5's callback pattern):

cards = arrayOf(findViewById<ImageButton>(R.id.card1),
                findViewById<ImageButton>(R.id.card2),
                findViewById<ImageButton>(R.id.card3),

cards[0].setOnClickListener { clickCard(0) }

// …cards[2], cards[3]
left!!.setOnClickListener { expression.append("(") }
// …right, plus, minus, multiply, divide append ")" "+" "-" "*" "/" in the same way
clear!!.setOnClickListener { setClear() }

4. The behaviour

Kotlin
private fun setClear() {
    var resID: Int
    expression.text = ""
    for (i in 0..3) {
        imageCount[i] = 0
        resID = resources.getIdentifier("card" + card[i], "drawable", packageName)
        cards[i].setImageResource(resID)
        cards[i].isClickable = true
    }
}

private fun clickCard(i: Int) {
    if (imageCount[i] == 0) {
        val resId = resources.getIdentifier("back_0", "drawable", packageName)
        cards[i].setImageResource(resId)   // show face-down
        cards[i].isClickable = false       // disabled from now on
        val value = data[i]
        expression.append(value.toString())
        imageCount[i]++
    }
}
Java
private void setClear() {
    int resID;
    expression.setText("");
    for (int i = 0; i < 4; i++) {
        imageCount[i] = 0;
        resID = getResources().getIdentifier("card" + card[i], "drawable", getPackageName());
        cards[i].setImageResource(resID);
        cards[i].setClickable(true);
    }
}

private void clickCard(int i) {
    if (imageCount[i] == 0) {
        int resId = getResources().getIdentifier("back_0", "drawable", getPackageName());
        cards[i].setImageResource(resId);   // show face-down
        cards[i].setClickable(false);       // disabled from now on
        int value = data[i];
        expression.append(String.valueOf(value));
        imageCount[i]++;
    }
}

Read those two methods as the spec executed. "Each of the 4 poker cards should only be selected once" is imageCount[i] == 0 plus isClickable = false. "When 'new game' or 'clear' is pressed, some disabled buttons may be enabled again" is isClickable = true in setClear(). The symbol listeners are one-liners appending to the formula TextView, which is also how the validity rules would be enforced (check what the previous item was before appending).

Expression evaluation and the JEP library

The program must evaluate strings like "(13 – 5) x (1 + 2)". The tutorial's own reasoning: "since the evaluation orders of different parts of the expression are different, the implementation requires an Expression Tree, which is quite complicated. To simplify our job, we rely on the JEP Library." JEP (jep-java-3.4-trial.jar) is copied into app/libs, right-clicked and "Add As Library"ed: the tooling habit from page 3. The smoke test parses and evaluates a string and shows the result in a Toast:

Kotlin
var jep = Jep()
val res: Any = try {
    jep.parse("(3 + 3) * (2 + 2)")
    jep.evaluate()
} catch (e: ParseException) {
} catch (e: EvaluationException) {
}
val ca = res as Double
Toast.makeText(this@MainActivity, ca.toString(), Toast.LENGTH_LONG).show()  // "24.0"

The real checker wraps exactly this, with the win test at the end:

Kotlin
private fun checkInput(input: String): Boolean {
    val jep = Jep()
    val res: Any = try {
        jep.parse(input)
        jep.evaluate()
    } catch (e: ParseException) {
        e.printStackTrace()
        Toast.makeText(this@MainActivity, "Wrong Expression", Toast.LENGTH_SHORT).show()
        return false
    } catch (e: EvaluationException) {
        e.printStackTrace()
        Toast.makeText(this@MainActivity, "Wrong Expression", Toast.LENGTH_SHORT).show()
        return false
    }
    val ca = res as Double
    return abs(ca - 24) < 1e-6
}
Java
private boolean checkInput(String input) {
    Jep jep = new Jep();
    Object res;
    try {
        jep.parse(input);
        res = jep.evaluate();
    } catch (ParseException e) {
        e.printStackTrace();
        Toast.makeText(MainActivity.this, "Wrong Expression", Toast.LENGTH_SHORT).show();
        return false;
    } catch (EvaluationException e) {
        e.printStackTrace();
        Toast.makeText(MainActivity.this, "Wrong Expression", Toast.LENGTH_SHORT).show();
        return false;
    }
    double ca = (Double) res;
    return Math.abs(ca - 24) < 1e-6;
}

Three things to notice. First, the exception handling is the input-validation layer: any parse or evaluation failure means "Wrong Expression" and a false return. Second, res as Double: JEP evaluates to a number typed as Any, so the cast is needed. Third, abs(ca - 24) < 1e-6 compares with a tolerance rather than ca == 24.0: division can produce values like 23.999999999, and a fixed-point check would call a correct answer wrong.

The button listener then closes the loop: read the expression text, and on checkInput(inputStr) == true show "Correct Answer" and call pickCard() for a new hand; otherwise show "Wrong Answer" and setClear().

Worked mini-example: one hand, traced

Deal the tutorial's test hand: cards 4, 5, 9, 10 (the four numbers in pickCard()'s testing stub). A solution: (9 – 5) × (10 – 4) = 4 × 6 = 24. Now trace the app, because this is what "reading a codebase" means at the exam:

  1. onCreate() binds views, sets listeners, calls pickCard(), which fills data and card, then setClear(): empty expression, imageCount all zero, card images set, all clickable.
  2. Tap "(": left's listener appends "(" to expression: "(" is legal because it is the first item. Tap "9": clickCard(2) (say card 3 is the 9) appends "9", shows the back image, disables the button. Tap "-": legal because the last item is a card. Tap "5": clickCard on the 5. Tap ")": legal after a card. Tap "*": legal after ")". Then "(" … "10", "-", "4", ")".
  3. Expression now reads "(9-5)*(10-4)". Tap "=": checkInput parses and evaluates it to 24.0, the tolerance test passes, "Correct Answer", new hand.
Pitfall

Why the brackets are mandatory here: typed without them, "9-5*10-4" evaluates by precedence as 9 − (5×10) − 4 = −45, not 24. The game's brackets are not cosmetic: they are the only way to override the multiply-before-subtract order. And the tutorial's own gaps (Task 5: make the deal random; require exactly four cards) mean the shipped code would accept "9-5" using two cards: the win rule "all four cards selected exactly once" is enforced by checking the used-counts before calling checkInput, which the starter code does not do.

Why a second toolkit exists

Chapter 3 introduced Flutter in one slide pair; Tutorial 4 teaches it hands-on. The motivation is the cross-platform problem from page 1: native development means one codebase per platform, web/hybrid compromises on feel, so a fourth option (own UI with its own renderer) was built. Flutter (Google, introduced May 2017) is an open-source SDK for Android and iOS whose engine, written mainly in C++, renders with Google's Skia graphics library and interfaces with the platform SDKs; apps are written in Dart.

Tutorial 4's pitch, its own three words: fast (Flutter code compiles to ARM or Intel machine code as well as JavaScript, for fast performance on any device), productive (hot reload: update code and see changes almost instantly, without losing state), flexible (control every pixel for customised, adaptive designs on any screen). Dart backs hot reload, compiles to native machine code, and Flutter relies on no browser or JavaScript runtime: apps for Android, iOS, Windows, macOS and Linux run directly, with performance the tutorial describes as comparable to native apps. Dart's asynchronous mechanism suits mobile work: network requests, file I/O, database operations. Users named in the tutorial: eBay, Tencent, Alibaba Group.

Source: COMP3330_Ch03_IDEs.pdf, slides 16-17; Tutorial_4.pdf, pages 3-5.

Flutter's mental model: widgets and setState

Two ideas replace the View tree and the listener code you now know:

  • Everything is a widget. The tutorial's example app starts from MaterialApp, "one of the widgets in Flutter's Material component library, which provides a Material Design interface and default theme for the application". Widgets are the buttons, texts and layout boxes: composable objects rather than XML elements and classes.
  • UI is rebuilt from state. setState() "is the method in Flutter used to notify the framework that the state has changed and the UI needs to be rebuilt". In the tutorial's counter app, _display is the text currently displayed on screen; a button click changes it and triggers the rebuild loop.
Compare

Card 24 in Android: listeners mutate widgets directly (expression.append, setImageResource, isClickable = false). Flutter's counter: the callback mutates plain state and calls setState(); the UI is a fresh description built from that state. Same callback idea you learned on page 5, different deal about who redraws the screen.

Setup and running, in brief

The tutorial's setup path (Linux via snap; macOS with git, Apple Silicon needing Rosetta; adding flutter/bin to PATH in the right rc file; then flutter doctor to check dependencies) ends in a dependency checklist: Android toolchain, Android Studio, CocoaPods on macOS. Note "the Dart SDK is bundled with Flutter; it is not necessary to install Dart separately". Running from VS Code: install the Flutter extension, Command Palette → "Flutter: new project", template type "Application", then Run → Start Debugging and try hot reload after a code change. Android Studio works too, with its Flutter plugin.

Check yourself

Q1

In the tutorial's Card 24 code, what happens when the player taps a card button a second time?

clickCard sets cards[i].isClickable = false after the first selection, implementing "once pressed, the card button should take no more effect (disabled)". The imageCount[i] == 0 guard backs it up.

Q2

Why does checkInput test abs(ca - 24) < 1e-6 instead of ca == 24.0?

JEP evaluates to a Double (res as Double); floating-point arithmetic after division is not exact, so the code compares within a small tolerance: a correct formula like (1/3)*72 should not be called wrong.

Q3

In Flutter, what does setState() do?

Tutorial 4's definition: "setState() is the method in Flutter used to notify the framework that the state has changed and the UI needs to be rebuilt": then build() re-executes and the new _display is rendered.
